# iTermate：让并发工作有序，让每个任务的状态可见

> **iTermate 是放在终端窗口旁的任务状态面板：把分散在多个窗口、标签页和分屏里的会话集中列出来，让你看清哪些任务还在运行、哪些已经结束，并能点击跳回对应终端。**

如果你经常同时开着几个项目，一边跑构建和脚本，一边让 Pi、Codex 等 AI 编程助手处理不同工作，iTermate 就能帮你少做一件事：**挨个切换终端，检查每个任务进行到哪了。**

它主要帮你做三件事：

- **集中管理**：把终端会话按窗口或项目目录整理到同一个面板，找任务不用再翻一排标签页。
- **查看状态**：显示已接入命令和 Agent 的运行、结束及成功／失败信息；Pi 还可以显示等待你回复和子代理仍在工作的状态，帮助你判断接下来该关注谁。
- **直接处理**：点击会话就能跳回对应终端继续操作，还能关闭会话、收藏常用项目，或归档暂时不做的 Pi 工作，之后再恢复。

例如，你同时让两个 Agent 改代码，另一个终端正在构建。你不用轮流盯着三块屏幕，而是从面板查看它们的状态：构建结束了，就去检查结果；Pi 正在等你确认，就先回答它；其余任务继续运行。

iTermate 专用于 macOS 上的 iTerm2，不替换终端。状态监控需满足 iTerm2 API 与相关集成条件。

**让多个任务同时推进，同时减少你找任务、查状态和来回切换的时间——这就是 iTermate 的核心价值。**

## 一、并发管理：从终端布局，转向工作全局

### 两种视图，适配两种思考方式

按 **Window** 分组，保留 Window → Tab → Session 的终端层级：窗口、标签页与分屏之间的关系一目了然，适合沿用已有的终端工作布局。

切换到 **Project Path**，会话按当前工作目录重新聚合。即使同一个目录下的工作分散在不同窗口和标签页，也能集中查看。对于同时维护多个项目的人，这意味着关注点可以从“任务开在哪个窗口”，转向“这个项目有哪些工作正在进行”。

这里的项目分组以**精确工作目录**为依据，不自动把不同子目录或 Git worktree 合并成一个仓库。

### 看见任务，也能直接接管任务

点击 Session，即可定位对应终端、标签页与分屏。分组可展开、折叠，支持全部展开与全部折叠；临时不需要关注的工作可以收起，而不必关闭正在运行的会话。

高频项目可以固定、收藏并设置专属颜色。当前聚焦项目还可以通过背景高亮保持位置感。在繁忙的工作区里，这些细节减少的是找位置、认标题和反复确认上下文的成本。

单个 Session 可以直接关闭，也可以对 Window、Tab 或项目分组发起批量关闭。关闭请求交由终端处理，不绕过终端原生的保护机制。

**并发不应意味着更多混乱。iTermate 提供的是面向并发工作的组织与操作层，而不是另一套需要迁移的终端系统。**

## 二、状态监控：看见“正在做什么”，而不只是“进程还在”

一个 Agent 进程仍然存在，不代表它还在工作；终端不再输出，也不代表任务已经完成。

iTermate 区分普通 Shell 命令和受支持的编程 Agent，分别使用终端活动信息与 Agent 生命周期事件呈现状态。对于 Agent，运行、完成、失败、空闲和等待回复有不同含义，不再统一压成一个忙碌指示灯。

| 状态信息 | 帮助你判断什么 |
| --- | --- |
| 运行中 | 哪些命令或 Agent 仍在推进工作 |
| 成功结束 | 哪些结果已经可以查看 |
| 失败结束 | 哪些会话需要排查退出状态或执行问题 |
| 等待回复 | 哪些 Pi 会话需要你的确认、选择、授权或补充信息 |
| Agent 空闲 | 哪些已接入会话当前没有在执行任务 |
| 子代理活动 | 哪些 Pi 会话仍有已确认活跃的子代理 |
| 运行与完成时间 | 一个任务已运行多久，或结束了多久 |

上述状态依赖对应终端与集成提供的有效信号；不是每种后端都能提供全部信息。无法确认时保留未知，而不是根据标题或进程名称补出一个看似确定的状态。

### 多 Agent 工作，重点是知道何时需要你

Pi 与 Codex 可以接入各自的生命周期状态。与单纯观察外层 CLI 进程相比，这能更准确地表达一次 Agent 工作是否开始、是否结束，而不是把长期驻留的交互进程一直显示为忙碌。

Pi 还支持更细的交互感知：明确的输入、选择与确认请求，以及回复结束后的待参与识别，可呈现为等待回复状态。问号不会因为你切到这个会话就自动消失，避免把“看过了”误认为“已经回答了”。

当 Pi 的子代理系统报告仍有活动时，面板用独立的像素分支动画标识。主 Agent 暂时没有输出，也不意味着后台子代理已经全部结束。这里显示的是**子代理活动标记**，不是每个子代理的任务树、日志或进度详情。

### 像素动画，不只是装饰

状态图标由 Canvas 绘制，通过像素形态、动画与颜色形成可扫读的视觉语言。普通命令与 Agent 的多种运行、成功、失败状态可以独立配置 Alien、Robot 或 Classic 风格及颜色，并在设置中预览。

等待回复使用专用问号；子代理活动使用分支动画；符合条件的 venom-cli 调试构建使用雷达动画。不同的工作状态有不同的视觉线索，不必逐行读文字才能判断下一步。

同时保留低干扰表达：空闲 Agent 使用弱化静态图标，支持的动画会响应系统“减少动态效果”偏好。

## 三、注意力调度：让需要处理的工作更容易被找到

### 一个快捷键，优先找到需要回应的 Agent

iTermate 可配置全局快捷键，按下面的优先级切换 iTerm2 中的其他 Agent Session：

**等待回复 → 已结束 → 运行中 → 空闲。**

同类候选按终端层级顺序循环，跳过当前会话，也不把普通 Shell 命令混入 Agent 轮转。

这不是自动安排 Agent 执行任务，而是把人的注意力优先带到需要介入的位置。你可以先回答阻塞工作的问题，再查看完成结果，而不必按窗口顺序逐个巡视。

该快捷键固定作用于 iTerm2，不随其他前台应用改变目标。

### 菜单栏保留一个轻量全局入口

无需展开完整面板，也可以从菜单栏查看两种终端中可确认的 Agent 运行总数，以及今天的成功完成次数。统计页进一步提供今日、本周、本月与累计汇总。

统计记录的是**被观察到的 Agent 成功完成转换次数**，不是独立业务任务数，也不是代码质量或产出价值评分。

菜单栏还提供收藏项目入口：在 iTerm2 中找到工作目录精确匹配的会话就直接激活，没有匹配时再以该目录打开新标签页；没有窗口时创建窗口。

可选的 macOS 完成通知，则让你在处理其他工作时仍能获知任务结束。通知根据退出状态区分成功、非零退出与未知结果，是否实际展示受系统通知权限与设置控制。

## 四、Pi 工作上下文：从识别当前任务，到保存和继续

### 用任务摘要替代难以辨认的终端标题

多个 Pi 会话同时运行时，仅靠终端名称很难分清各自的目标。

iTermate 的 Pi 集成可以基于当前分支的可见对话生成简短任务标题，在安全空闲时补生成，并在成功回复结束后后台更新。面板优先显示任务标题，悬停仍可查看原始终端标题，也支持右键手动刷新。

它回答的是“这个会话在处理什么”，而不只是“这个会话运行了什么程序”。生成失败时保留已有标题；没有有效摘要时回退原始标题，不阻断终端使用。

### 把暂时不做的工作，从桌面移入归档

对于已空闲、没有待处理输入和活跃子代理的 Pi 会话，可以执行归档：生成会话摘要，保存原生会话记录与当前分支位置，校验成功后请求 Pi 正常退出，并在确认安全时关闭对应分屏。

归档后，主面板的 Archive 分区与设置页提供恢复入口。你可以先通过摘要回顾工作，再在原工作目录的新终端中继续。恢复使用独立可写副本，不直接改写归档快照；只有新 Pi 报告打开了预期副本，才确认恢复成功。

归档支持从面板移至系统废纸篓。原始 Pi 文件不会因此被删除。

**这让并发工作不再只有“保持所有终端打开”这一种维持上下文的方式。** 当前需要的工作留在面板，暂时搁置的工作通过会话快照保存，回来时再继续。

归档保存的是 Pi 会话，不是整个项目备份，不会快照工作目录、外部服务或子代理工作区。

## 五、原生伴随体验：不替换终端，不抢占工作中心

面板仅跟随当前前台 iTerm2 窗口显示；切换到其他应用时自动隐藏。可关闭面板显示，也可调整宽度与停靠偏好。

应用采用 SwiftUI 与 AppKit 构建，提供系统、浅色和深色外观，模糊或不透明背景，以及强调色、字体、字号、项目标题、Tab 标题和时间格式设置。

iTerm2 通过官方 API 与随应用分发的 Python Bridge 连接。无需 macOS 辅助功能权限，但与终端通信需要相应的自动化授权。iTerm2 Bridge 由应用安装管理，无需单独配置 Python。

状态链路也考虑了长时间工作中的恢复问题：心跳与有限租约避免过期活动无限延续，序列校验减少迟到事件覆盖新状态，Pi 支持在状态缺失时向活跃实例查询恢复。标题栏刷新可重启 iTerm2 Bridge，不必重启终端 Session。

这些机制的目标是让状态更可信，而不是承诺永不丢事件或跨后端完全一致。

## 六、完整能力清单

以下按当前仓库中已实现的用户能力归类；源码具备能力，不等于所有公开安装包或已安装集成都已包含对应更新。

### 工作区与并发会话管理

- 仅支持 iTerm2，跟随当前前台 iTerm2 窗口。
- 可配置面板显示开关；离开 iTerm2 时自动隐藏。
- 展示 Window、Tab、Session 层级。
- 按 Window 或精确 Project Path 分组，支持同一目录跨窗口与标签页聚合。
- 可选 Tab 子分组标题，支持分组展开、折叠及全部展开、全部折叠。
- 点击会话定位窗口、标签页与分屏，显示当前焦点。
- 单个会话关闭，以及 Window、Tab、项目分组批量关闭请求。
- 项目固定、收藏、自定义颜色与聚焦项目背景透明度设置。
- 菜单栏收藏项目导航，复用 iTerm2 已有匹配会话或打开新标签页／窗口。
- 面板宽度调整、左右停靠偏好。

### 状态监控与注意力管理

- 区分普通 Shell 命令与 Agent 活动来源。
- 呈现可确认的运行、成功、失败、结束与 Agent 空闲状态。
- Pi 待回复识别，覆盖明确交互及可选的回复语义辅助判断。
- Pi 子代理活动标记与专用分支动画。
- 运行／完成时间显示开关，以及紧凑、详细时间格式。
- Agent 与 Shell 状态分别配置像素动画风格及颜色，支持预览和颜色恢复默认。
- 等待回复专用问号、子代理分支、venom-cli 调试构建雷达。
- 支持部分动画的减少动态效果适配。
- 可选系统完成通知，显示成功、非零退出或一般结束信息。
- iTerm2 Agent 全局快捷轮转：等待回复优先，随后为已结束、运行中、空闲。
- 菜单栏显示 iTerm2 Agent 运行数量与今日成功完成次数。
- 今日、本周、本月、累计 Agent 成功完成统计，按日持久化。
- 连接、状态失效与部分操作错误的界面反馈；未知状态不冒充空闲。

### Agent 与 Shell 接入

- Pi 生命周期集成，支持安装／更新后重新加载。
- Codex 生命周期集成，通过 TTY 与原生 rollout 数据被动识别；无需 hooks 或包装器，直接运行 `codex`。
- Agent 状态优先于普通 Shell 活动，避免外层常驻 CLI 掩盖真实工作状态。
- iTerm2 通过 Bridge 与可用的 Shell Integration 观察普通命令。
- 基于明确 Session 身份或可见 TTY 的真实进程父子关系匹配状态，不按标题或目录猜测归属。
- 心跳、有限租约、消息序列与唤醒清理，减少陈旧状态残留。
- Pi 活跃会话状态主动恢复；只读状态查询不调用模型。
- iTerm2 Bridge 刷新，不重启用户终端会话。
- venom-cli debug build 的特定进程观察与雷达标识，覆盖可确认的构建、安装、重建和日志阶段；不是通用调试器。

### Pi 标题、归档与恢复

- 当前任务的简短中文标题，安全空闲时补生成、成功回复后后台更新。
- 手动刷新任务标题，悬停查看原始终端标题，失败保留旧内容。
- 基于明确活跃身份执行归档，不以目录或文件修改时间猜测目标会话。
- 归档摘要、完整原生 JSONL 记录、历史分支与当前分支锚点。
- 归档完整性校验，成功后请求正常退出，并在安全条件成立时关闭对应分屏。
- 主面板 Archive 折叠分区与设置页归档列表，悬停查看摘要。
- 在原工作目录的新 iTerm2 会话中恢复到独立可写副本。
- 恢复确认、相同会话活跃时的重复恢复拦截，以及损坏记录或目录缺失检查。
- 归档移至系统废纸篓，不删除原始 Pi 会话文件。

### 可选本地模型能力

- Laya、Vela 两种本地决策模型选项，以及安装、启动和服务状态管理。
- 可选辅助判断 Pi 最新回复是否要求用户参与，不要求文本必须带问号。
- 在 Agent 回复结束的生命周期节点调用，不持续扫描终端屏幕。
- 独立的本地 API 服务开关与状态辅助开关。
- 带 Bearer 认证的本机决策、Session、问题判断和健康检查接口。
- 连接提示与 API Token 复制入口，供可信本地客户端接入。
- 模型不可用时保留明确生命周期信号，不自动切换另一模型兜底。

### 原生应用与个性化

- SwiftUI／AppKit 原生 macOS 界面与菜单栏入口。
- 登录时启动。
- 系统、浅色、深色外观；模糊或不透明背景。
- 强调色、字体、字号、项目标题样式、Tab 标题显示设置。
- 状态动画独立配置、颜色预览与偏好持久化。
- 自定义全局快捷键录入、清除与冲突反馈。
- Sparkle 更新检查与手动检查更新入口。
- iTerm2 Bridge 随应用分发及安装管理。

## 七、能力边界：专业的介绍，也应说明前提

**仅支持 iTerm2**。面板、会话操作、全局 Agent 轮转和收藏项目入口都面向 iTerm2，不提供其他终端后端。

**Pi 与 Codex 不是功能镜像。** Pi 的回复语义判断、子代理活动、任务标题、归档恢复有专门集成，不应直接推广为 Codex 同样具备。Codex 采用本机进程与原生 Session 数据的被动观察，不安装 hooks，也不解析终端文字；因此可可靠识别运行、完成和中断，但无法可靠区分普通提问与明确等待输入，界面会保守显示而不猜测。

**本地分类和任务摘要是两条不同链路。** 可选 Laya／Vela 分类在本机运行，需要 Apple Silicon 与 macOS 14 或更高版本；它是实验性判断，不保证准确率，也不代表自动授权。Pi 任务标题和归档摘要则调用该会话当前模型，会消耗额度，并可能向配置的模型服务方发送选取的可见对话，因此不能宣传为“所有内容绝不离开本机”。

**归档不是加密备份。** 会话记录可能包含敏感信息，虽然使用当前用户私有目录与权限限制，但归档本身不加密，不应直接公开或提交到代码仓库。

**它管理并发工作的可见性，不替你编排执行。** iTermate 不是 Agent 调度引擎，不提供任务自动分派、依赖图调度、并发配额或执行结果质量验收；成功状态与完成计数也不等于业务目标已经达成。

应用要求 macOS 13 Ventura 或更高版本，公开下载版面向 Apple Silicon。当前公开构建采用 ad hoc 签名，未经过 Apple 公证；安装时应核对发布校验信息，并按 macOS 的提示处理首次打开限制。

## 八、适合怎样的工作现场

**多项目并行开发。** 一个项目在构建，另一个在跑脚本，第三个正在由 Agent 修改。按目录组织会话，保留每个项目的工作视野，减少在终端布局中寻找任务的时间。

**多个 AI 编程会话并行。** Pi、Codex 分别处理不同工作，你需要知道哪些还在执行、哪些已结束，以及哪些 Pi 会话正在等你回答。状态面板配合快捷轮转，让人工介入更有顺序。

**长时间构建与调试。** 命令耗时、完成结果和通知提供反馈；使用符合条件的 venom-cli 调试构建时，雷达图标进一步标识对应活动。

**跨时段推进任务。** Pi 工作暂时搁置时归档，回来通过摘要找回上下文，再从原目录恢复。无需为了“以后还要继续”而始终保留所有终端分屏。

## 结语

并发工作的上限，不只取决于能同时启动多少任务，也取决于人能否及时理解状态、处理阻塞并接住结果。

**iTermate，让终端里的并行工作可见、可定位、可接管。**

保留成熟终端的可靠体验，在它旁边增加一层面向多任务与 AI Agent 的工作视野。任务可以同时推进，你不必同时盯住每一块屏幕。
