title: Pi状态恢复
summary: Pi状态恢复的适用条件、实现边界及复查要点。
---

- [2026-11-05] CTX-pi-status-recovery — Pi 状态主动恢复；适用范围： Pi已存在但Agent状态缺失时的认证查询、iTerm2恢复、乱序防护和旧集成能力边界。实现入口： `integrations/pi/iTermate-integration.ts`, `iTermate/PiSessionArchives.swift`, `iTermate/ItermBridge.swift`, `iTermate/SessionNotifications.swift`, `iTermateBridge/iTermateBridge.py`；权威入口： `integrations/pi/iTermate-integration.ts`, `iTermate/PiSessionArchives.swift`, `iTermate/ItermBridge.swift`, `iTermate/SessionNotifications.swift`, `iTermateBridge/iTermateBridge.py`；复查条件： 状态协议、Pi生命周期、私有发现身份、补查调度、连接代际、接收端序列或完成追踪变化时复查。
- [2026-11-05] Pi私有端点以supportsStatus声明能力；status验证token与原生Session ID，返回实例身份、状态、来源ID/单调序列、子代理标记和可选完成证据；与主动推送共用状态派生，回复分类默认normal而不产生unknown；子代理观测缺失仍不能误报finished。不发布状态、不调用模型、不归档或推进Pi；缓存观测可更新，但不使用canArchive推断空闲。Store在既有两秒定时器中扫描缺失Agent状态的会话，最多4个在途请求，每次3秒截止；轮转位置只在实际预留请求后前移，满额轮次保持游标，避免慢端点阻塞后续健康候选；仅用明确iTerm2 Session ID唯一匹配。查回后重新核验实例与当前快照，连接/唤醒/停止代际失效的结果丢弃；iTerm2接收端只填补缺失Agent状态，不覆盖新推送或聚焦后的idle。查询快照与正常Pi推送共用单调序列；接收端拒绝迟到消息并保留detached保护，running/awaitingInput仍有租约。集成持有按状态与 turn 身份更新的 `statusChangedAt`，推送与只读恢复共用，Bridge 校验并透传，避免 App/Bridge 重启为同一等待事件重新计时；finished 继续使用 completedAt。旧集成无该字段时保留 Bridge 时间兜底，但不能保证 awaitingInput 手动确认跨 Bridge 重启恢复，需 Agents 更新并在 Pi reload。每轮正常/失败finished提供稳定completionId、Unix秒completedAt和exitStatus；recentCompletions保留当前集成运行期最近64条，快照复制数组并跨后续running/idle及生命周期缺失保留，latestCompletion继续兼容；通知/统计按ID逐条去重，不要求相邻running→finished采样。首次观察到的历史完成不补发；aborted不生成成功完成；Session启动/重载清空列表，断开期间超过留存上限而被挤出的事件仍无法补齐。Bridge按原生Session ID保存已查看完成ID，只抑制同一完成；异步激活/快捷键/项目入口在等待前捕获身份，迟到回调不确认新结果。原生焦点监听在刷新焦点前捕获状态，刷新后仅对前台当前终端窗口获得键盘焦点、当前 Tab 或 pane 的激活确认同一 finished 事件；单独应用激活（可能打开设置窗口）、失焦、后台 Tab/pane 更新及刷新期间的新结果不被确认，running/awaitingInput 保留。旧集成缺少completionId时保留原兜底，缺少supportsStatus不查询，需Agents更新并reload生效。
