---
title: 视觉设计与资源验收
summary: 视觉设计与资源验收的适用条件、实现边界及复查要点。
---

- [2026-11-06] 按具象参考制作状态组件或动画，先明确主体、伴随元素、尺寸关系和状态动作；未经确认，不以仅保留像素、配色的抽象图案替换角色。实际画面MUST 能辨认主体及伴随元素，并用已确认角色动作表达状态。
- [2026-11-05] 新图标参考或否定上一视觉方向后，若下一步生成消耗配额或产生多个候选，先拆解可复用视觉语言与禁止复制的主体元素，提交修订提示词或概念确认后再生成；风格反馈本身不等于立即批量生成许可。
- [2026-11-05] MenuBarExtra使用自定义PNG/PDF/asset label时，SwiftUI.frame可能无法约束实际图像尺寸；先在NSImage层设目标点高并按原宽高比算宽，再创建Image(nsImage:)。真实截图核对目标点尺寸，不能把源像素数当显示高度；旧案例目标16pt并非固定产品规格。
- [2026-11-05] 菜单栏源PNG保留原始高分辨率，不为画布留白或缩小显示先降采样到24px等小尺寸；模板化仅转换颜色/透明度。用运行时尺寸或高分辨率画布控制显示，以file/sips核对源像素、assetutil或构建产物核对加载资源。
- [2026-11-05] 图标仍过大或过小时，同时检查容器和非透明/非空白绘制边界；矢量优先调整viewBox或内部留白。比较前后可见边界或比例，在目标背景查看最终预览，并以相关构建或资源编译确认仍可加载；仅修改frame不证明可见缩放生效。
- [2026-11-05] 以Xcode或Apple系统设置为视觉参考时，先核对HIG、SDK和参考应用再选原生容器；避免自绘卡片、导航背景或Liquid Glass覆盖系统材质、间距与交互，仅在原生无法表达功能时最小自定义。用目标SDK和系统检查控件外观、强调色、容器尺寸及降低透明度等辅助功能。
- [2026-11-09] iTermate设置由Settings scene、顶部TabView及grouped Form承载；当前不使用侧边栏。旧sidebarAdaptable建议不能覆盖现有顶部标签规格，具体布局以SettingsViews.swift与iTermateApp.swift为准。
- [2026-11-05] 用户反馈图标或控件仍然过大/过小。只调整外层 frame 或 layout 数值后没有直接检查资源的实际绘制边界。
- [2026-11-05] 验收检查：记录修改前后的可见绘制边界或缩放比例。在目标背景上查看最终渲染预览。运行相关构建或资源编译验证图标仍可加载。
- [2026-11-05] 用户以 Xcode、系统设置或 Apple 最新设计作为界面参考。当前实现通过自绘卡片、背景、圆角或固定尺寸模仿系统界面。
- [2026-11-05] 先把参考图拆解为可复用的视觉语言，并明确MUST NOT 复制的主体元素。先提交修订后的提示词或概念供用户确认，再调用图像生成工具。不要把用户的风格反馈直接解释为立即批量生成许可。
- [2026-11-05] 用户提供新的图标风格参考或否定上一轮视觉方向。下一步图像生成会消耗配额或产生多个候选。
- [2026-11-05] 验收检查：用户已明确确认当前提示词或概念方向。提示词分别列出继承的视觉特征和禁止复制的参考元素。确认前未调用图像生成工具。
- [2026-11-05] 验收检查：使用最新 SDK 构建，并在最新系统运行时检查侧边栏、工具栏、表单和控件外观。界面跟随系统强调色、侧边栏尺寸及降低透明度等辅助功能设置。标准容器可表达的区域不存在手工 Liquid Glass、自定义导航背景或硬编码系统外观。
