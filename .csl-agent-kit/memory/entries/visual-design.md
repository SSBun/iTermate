title: 视觉设计与资源验收
summary: 具象参考与图像生成确认边界、菜单栏资源尺寸、原生 macOS 界面及视觉验收经验。
---

- [2026-11-06] 按具象参考制作状态组件或动画时，MUST 先明确主体、伴随元素、尺寸关系和状态动作；未经确认，MUST NOT 以仅保留像素、配色的抽象图案替换角色。实际画面 MUST 能辨认主体及伴随元素，并用已确认角色动作表达状态。
- [2026-11-05] 用户提供新图标参考或否定上一视觉方向后，若下一步图像生成消耗配额或产生多个候选，MUST 先拆解可复用视觉语言与禁止复制的主体元素，提示词 MUST 分别列出继承的视觉特征和禁止复制的参考元素；MUST 提交修订提示词或概念并取得用户明确确认后再调用图像生成工具。MUST NOT 把风格反馈直接解释为立即批量生成许可。
- [2026-11-05] MenuBarExtra 使用自定义 PNG/PDF/asset label 时，SwiftUI.frame 可能无法约束实际图像尺寸；MUST 先在 NSImage 层设目标点高并按原宽高比算宽，再创建 Image(nsImage:)。MUST 用真实截图核对目标点尺寸，MUST NOT 把源像素数当显示高度；旧案例目标 16pt 并非固定产品规格。
- [2026-11-05] 菜单栏源 PNG MUST 保留原始高分辨率，MUST NOT 为画布留白或缩小显示先降采样到 24px 等小尺寸；模板化 MUST 仅转换颜色/透明度。MUST 用运行时尺寸或高分辨率画布控制显示，以 file/sips 核对源像素、assetutil 或构建产物核对加载资源。
- [2026-11-05] 曾在用户反馈图标或控件仍过大/过小时，只调整外层 frame 或 layout 而未直接检查资源绘制边界。遇到此类反馈，MUST 同时检查容器和非透明/非空白绘制边界；矢量 SHOULD 优先调整 viewBox 或内部留白。MUST 记录修改前后的可见边界或缩放比例，在目标背景查看最终渲染预览，并以相关构建或资源编译确认仍可加载；仅修改 frame 不证明可见缩放生效。
- [2026-11-05] 曾通过自绘卡片、背景、圆角或固定尺寸模仿 Xcode、系统设置或 Apple 最新设计。以这些应用为视觉参考时，MUST 先核对 HIG、SDK 和参考应用再选原生容器，MUST NOT 在标准容器可表达的区域以自绘卡片、导航背景、手工 Liquid Glass 或硬编码系统外观覆盖系统材质、间距与交互；仅在原生无法表达功能时做最小自定义。MUST 用目标 SDK 和系统检查适用的侧边栏、工具栏、表单和控件外观、系统强调色、容器尺寸及降低透明度等辅助功能；参照 Apple 最新设计时，MUST 使用最新 SDK 构建并在最新系统运行时检查。真实运行验证 MUST 遵守项目 lessons 的启动授权边界。
- [2026-11-09] iTermate 设置由 Settings scene、顶部 TabView 及 grouped Form 承载；当前不使用侧边栏。MUST NOT 用旧 sidebarAdaptable 建议覆盖现有顶部标签规格，具体布局以 SettingsViews.swift 与 iTermateApp.swift 为准。
