## Decisions

- 2026-10-14 重新调查：此前“实时标题没有摘要通路”的结论已不适用于当前源码。`iTermate/PiSessionArchives.swift:150-160` 优先使用有效 Pi 发现记录的 `taskSummary`，缺失时回退终端名；`iTermate/iTermateApp.swift:1084` 调用该入口。
- 两次只读读取当前存活进程的发现记录，共 7 个 Pi 实例：skills 与 native-short-reader 两个实例有 `taskSummary` 且声明 `supportsTitleRefresh: true`；其余 5 个实例均无摘要，也不声明该能力。第二次读取全部记录更新时间距采样在 0–1.5 秒内，不是过期残留。
- skills 实例发布的摘要为“调整任务表格与资源链接并验证兼容性”，与截图一致。调查时 native-short-reader 也已发布“按新版规范更新故事挽留弹窗主题内容”；不能把截图时只有一个的状态当作调查时仍然成立。
- 当前本会话的 ITERM_SESSION_ID 精确匹配无摘要的 iTermate 实例（PID 48907）。当前源码的发现元数据无条件包含 `supportsTitleRefresh: true`，而该进程持续发布的元数据没有它，证明其运行中的集成不具备当前源码的能力声明；结合不同实例的能力分层，主要差异是各常驻 Pi 进程加载的集成代际不一致，不是 UI 统一拒绝显示摘要。
- 仓库与用户安装的集成脚本 SHA-256 相同：`5735e30786f685f524f32637b1741512a4508121d23af6ec2c88295f4a3cf445`。磁盘更新不等于旧进程已重载；未从进程内存导出源码，不断言具体旧版本号。
- 当前自动摘要在 `agent_settled` 后启动，要求有成功的助手文本、当前模型与空闲状态；会调用当前 Pi 模型，60 秒超时。启动/重载与分支切换清空缓存，不自动为历史对话补生成；下一轮开始取消在途生成。自动失败被吞掉、保留旧标题，没有记录失败原因。故即使更新集成，也不保证工作过程中即时改名。
- 当前实时摘要通路是 Pi 专用发现协议。普通 shell 与 Codex 状态适配没有同等 `taskSummary` 通路，不能期望截图中每一行都通过此功能获得任务名。
- 截图里的 pi-subagents 加载错误不是当前标题缺失的直接证据；标题更新不以 fleet 查询成功为必要条件，不据此归因。
- 未触发手动刷新或额外模型调用，未改变用户安装态、进程或产品文件，未运行测试。没有实时 UI 截图，因此仅确认 native-short-reader 的摘要已发布，不声称已经在屏幕上显示。

## Plan

1. 向用户解释当前主要原因：常驻 Pi 会话集成能力不一致，缺失摘要时回退目录/shell 标题。
2. 建议旧 Pi 会话重载集成后，在空闲时右键 Refresh Session Title，或等待下一轮正常回复完成；不代用户执行重载或模型请求。若重载仍缺少能力，应进一步核验加载诊断与运行时模块缓存。
3. 如用户要求修复，再单独对齐是否需要重载后补生成、失败可观测性与非 Pi 会话摘要支持；本次不授权实现。
