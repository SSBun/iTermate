# 定位面板标题在有剩余空间时提前截断的原因

| Field | Value |
| --- | --- |
| Status | Pending (2026-10-22 15:39) |
| Kind | Plan |

## Scope

仅定位截图标题提前省略的原因并提出修复方向；不修改产品源码、不重启应用或 Bridge、不调用模型刷新标题、不运行测试。

## Target

- [ ] T1: 通过标题原文与行布局的证据，明确截图中的省略来自标题数据还是布局压缩，并给出最小修复方向；本阶段不修改产品源码。

## Decisions

- 已确认：`iTermate/iTermateApp.swift:944–953` 将原始标题直接传给 Text，并使用 lineLimit(1) 与 tail 截断；右侧仍有 Spacer。没有对 Agent 标题设置短字符上限。
- 已确认：`integrations/pi/iTermate-integration.ts:587–589,621–623,992` 仅要求模型标题为非空字符串，非空结果原样发布；`iTermate/PiSessionArchives.swift:150–165` 允许换行，只检查非空与传输长度。因此带换行或模型自带省略号的结果均可能直接显示。
- 已进行非测试的原生离屏渲染对比：通过 stdin 执行 SwiftUI ImageRenderer，以相同 HStack/Text/状态占位/Spacer/关闭按钮宽度，在 460pt 宽度渲染三种字符串；Vision OCR 在内存读取像素，不保存图片或修改源码。单行“1. 终端界面重构并调整项目布局”完整可见；“1. 终端界面重构\\n2. 调整项目布局”只剩第一行并出现截断标记；原文本身含省略号时仍显示省略号。证明硬换行配合单行限制可在横向空间充足时产生该现象，而非单凭截图将其归因于宽度分配。
- 当前现场元数据已被后续自动摘要替换为单行“用户截图显示标题被截断，需查明原因并给出修复方案”；没有截图时刻旧 taskSummary 的历史副本。本轮未主动刷新标题，因此无法最终确认截图原文是换行还是字面省略号。换行与编号标题的截图模式一致，是目前最有证据支持的解释，但不是历史原文的直接证明。
- 最小候选修复：若确认换行，仅在单行展示层将换行符折叠为空格，原始标题及悬停提示保留；真正超宽时仍使用省略。若省略号已由模型生成，布局无法恢复不存在的后半段，应修复生成结果或重新生成，不能用扩大 Text 宽度冒充修复。
- 本轮未修改产品、配置、集成或用户安装态；未启动应用/Bridge，未运行单元测试或项目测试套件。先前实现任务的证据和审查记录不作改写。

## Plan

1. 在现象再次出现时只读取得对应 taskSummary 或完整悬停标题，核对换行符、Unicode 分隔符及字面省略号，补齐截图历史原文无法恢复的证据边界。
2. 根据原文选择展示层换行折叠或模型标题生成修复；取得执行授权后才进入实现，不扩大到其他布局。
3. 验证普通单行、含换行、字面省略号和真正超宽标题；只使用获授权的构建与离屏渲染，不自行重启应用或运行测试。
