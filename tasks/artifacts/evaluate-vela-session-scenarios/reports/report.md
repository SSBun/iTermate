# Vela 终端状态场景评估

## 结论

本轮 40 条预标注合成场景中，Vela 原始分类正确 39 条（97.5%）；现有阈值下只展示 18 条，展示正确率为 18/18（100%）。不能把后者解释为全场景可靠：30 条有明确状态的场景仅展示 18 条（60%），尤其等待回复场景只展示 1/10。

## 方法与证据

- 实际模型：`vllm-sr/Vela-2.0-0.3B`，实际 provider：`vela`。
- 调用已运行服务的 `/health` 和 `/v1/session`；请求前后验证配置、分析许可、provider 和服务 instance 一致，响应模型一致。没有启动、重启或修改 App/模型服务。
- 输入：[scenarios.json](../evidence/scenarios.json)，在本轮推理前固定；运行、等待回复、空闲、未知各 10 条，每类中文和英文各 5 条。没有依据输出修改标签或删掉错题。
- 复跑脚本：[evaluate.py](../evidence/evaluate.py)。在当前目录通过 `python3 ../evidence/evaluate.py` 运行，需要本机已有 Vela 服务。仅向回环地址发送构造文本，鉴权凭据不写入结果。每轮创建独立结果文件。
- 原始结果：[results-20261012T061500650477Z.json](../evidence/results-20261012T061500650477Z.json)，包含完整输入、预期标签、原始概率、附加评分、耗时及错误记录。数据 SHA256 已写入结果，复跑使用同一数据可核对。
- 每条单次请求，40/40 成功，无 HTTP 或超时失败。允许 429 最多重试两次，但本轮没有发生重试。
- 不向模型传入预期标签、场景类别或语言标记，只传入 `text`。所有输入不足 1500 字符，无截断或为了通过模型预算而缩短文本。
- 使用已有服务端提示词，不调参、不改产品逻辑。本轮没有重载 worker，因此不单凭磁盘源码声称运行中提示词版本的精确身份。

标签约定：依据最新可见事件；服务持续监听属于 running；失败后明确退出且不需要回复属于 idle；仅有历史或不足以确认当前活动的片段属于 unknown。idle 不等于执行成功。

### 唯一分类错误：I03

输入：

```text
构建失败：找不到依赖。
进程已退出，退出码 1。没有自动重试或待确认操作。
user@mac project %
```

预期为 idle；模型预测 unknown，选中概率约 42.82%。按本次标签约定，失败但已结束、不等用户回复应为空闲，而非运行或等待回复。结果未达到展示条件，所以不会展示错误状态标签。

## 现有展示规则的影响

按 Bridge 当前规则计算：

1. 已有明确生命周期状态时不使用模型标签；这里假设没有该状态且估计尚未过期。
2. 选中类别必须为 running、awaitingInput 或 idle，且其 `probabilities[choice] ≥ 0.85`。
3. awaitingInput 还要求 `needs_reply.noul ≥ 0.6`。
4. 使用的是选中类别的概率，不是单独的 `confidence` 字段。

| 预期类别 | 正确分类 | 最终展示 | 展示但错误 |
| --- | ---: | ---: | ---: |
| running | 10/10 | 9/10 | 0 |
| awaitingInput | 10/10 | 1/10 | 0 |
| idle | 9/10 | 8/10 | 0 |
| unknown | 10/10 | 0/10 | 0 |

- 全部场景展示覆盖率：18/40 = 45%。unknown 本就应该不展示，因此另报明确状态场景覆盖率：18/30 = 60%。
- 展示正确率：18/18 = 100%，只代表被保留的 18 条。
- unknown 误展示：0/10。
- 明确状态中分类正确但不展示：11 条（R04、A02–A10、I09）；另有 10 条正确判为 unknown，按设计不展示。
- A01 是唯一显示 Reply? 的等待输入样本。

### 等待回复被过滤的原因

10 条全部选择 awaitingInput，但其中 9 条未显示：

- A02、A04、A05、A08、A10：类别概率已达 0.85，仅被附加 needs_reply 阈值拦截。
- A03、A06、A07：类别概率和 needs_reply 都未达阈值。
- A09：needs_reply 已达阈值，但类别概率未达 0.85。

例：A04 的输入为 `I cannot continue without the target branch name. Please provide it. Waiting for your reply.`，分类概率约 99.88%，但 needs_reply 仅约 0.192，最终不显示 Reply?。

这证明本轮样本中两个输出并不一致，不能因为原始分类 97.5% 就认为实际等待回复提示同样可靠。此结论只描述现有规则，未据此修改阈值或提示词。

## 局限

- 这是单轮、小规模、均衡的合成集，不是真实终端数据分布，也未做多次稳定性或跨服务实例测试。
- 多数场景明确写出“任务已结束”“等待回复”等线索，偏向检验基本语义和最新事件优先级，成绩很可能高于噪声终端场景。
- 中文与英文不是成对翻译；分数差不能用于断言语言能力差异。
- 未覆盖长文本 1500 字符截断、ANSI/TUI 重绘、多分屏混合、长时间无输出但仍计算、提示词注入、频繁状态切换等真实难点。
- unknown 有些标签依赖人工约定；本轮成绩应理解为对这套预先固定约定的符合程度。
- 没有操作真实会话，没有运行项目测试套件，也没有验证 App 的真实 UI 显示。本轮仅运行用户明确授权的场景评估。
