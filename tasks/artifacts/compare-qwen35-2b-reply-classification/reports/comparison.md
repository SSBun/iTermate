# Qwen3.5-2B 回复状态分类实测

## 结论

在相同固定样本、提示词和生成参数下，2B 三轮均正确 37/40（92.5%），优于前轮 Vela 的 82.5% 和 0.8B 的 56.7%。截图对应的计算结果回复三次均正确判为 normal；这说明该复现样本已经判对，不代表 iTermate 生产误判已修复。

2B 值得进一步验证，但暂不直接替换现有分类器：它减少了误报，同时比 Vela 多漏掉一种隐含确认场景；卸载后的首次请求约 2.69 秒，也超过现有 800 毫秒截止。当前产品源码和配置均未修改。

## 安装与运行

- 复用现有 Ollama 0.40.6，没有升级或重新安装运行环境及 Homebrew 依赖。
- 仅新增 `qwen3.5:2b`，模型文件大小 3,117,475,695 字节，约 3.12 GB。
- 实际模型 digest：`dfaf2605162e689c8cac330dc4a190c4c50ad30aa47814a8fe9b79fa5127e97e`。
- 实际后端：MLX、safetensors、mxfp8；服务报告参数量 2.2B。加载后服务报告 `size_vram` 为 3,160,524,608 字节，不能将其视为整个进程峰值内存。
- 机器沿用 Apple M4、32 GiB 内存。Ollama 沿用原有回环服务，未启用云推理、未新增登录服务；模型下载使用前轮已有的本机代理设置，地址安全检查未关闭。
- 原有 0.8B 保留，未下载 4B；未启动或重启 iTermate/Bridge。

## 方法与可比性

原样读取前轮不可变的 [40 条语料](../../compare-qwen35-08b-reply-classification/evidence/cases.json) 和 [正式结果中的最终协议](../../compare-qwen35-08b-reply-classification/evidence/results-20261020T094324Z.json)，不重新编写提示词或标签。

业务定义仍是“最新助手回复是否请求或等待用户参与”，包括回答、选择、确认、授权和补充信息，不等同于是否出现问号。类别 normal/question 各 20 条；各类别中文、英文各 10 条。只有截图原文是真实故障样本，其余 39 条是人工合成。

- 使用前轮相同英文 system prompt、两个合法 JSON 输出模板，严格解析 `{"label":"normal"}` 或 `{"label":"question"}`。
- `think=false`，temperature 0、seed 42、上下文 4096、最大生成 32 token，未使用强制 JSON 解码。
- 保留相同三轮次数及洗牌种子，只调用 2B，共 120 次正式请求；无静默重试、删题或正式评估后的调参。
- Vela 与 0.8B 引用前轮保存的指标，本轮没有重新推理。虽然设备、样本与协议一致，但测量时间和调度不同，因此延迟不是同场配对实验，不能直接归因于参数量差异。
- 三轮重复不是 120 个独立样本，准确率不代表生产分布或统计显著性。

语料 SHA-256：`ab4894e91d34e887c0ca8a05d9ea53bddb41831f2d71c40694b76c63505fdb91`。

## 分类结果

| 指标 | Vela 0.3B（历史） | Qwen 0.8B（历史） | Qwen 2B（本轮） |
|---|---:|---:|---:|
| 正式请求数 | 120 | 120 | 120 |
| 正确分类 | 99/120（82.5%） | 68/120（56.7%） | 111/120（92.5%） |
| 各轮正确样本数 | 33、33、33 / 40 | 22、23、23 / 40 | 37、37、37 / 40 |
| 普通回复误报为等待 | 18/60（30.0%） | 52/60（86.7%） | 3/60（5.0%） |
| 等待请求漏报为普通 | 3/60（5.0%） | 0/60（0%） | 6/60（10.0%） |
| 协议、HTTP、格式错误 | 0 | 0 | 0 |
| 截图原文 | question，三次均错 | question，三次均错 | normal，三次均对 |

2B 中文正确 57/60，英文正确 54/60。每轮都是同样三条错例：

| ID | 原文要点 | 期望 | 实际 | 影响 |
|---|---|---|---|---|
| N-EN-05 | 助手引用 `input('Delete this file? [y/N]')`，并说明没有执行命令 | normal | question | 把代码里的提问误当作当前等待 |
| Q-ZH-07 | 方案已准备好。确认后我再开始修改。 | question | normal | 漏掉无问号的隐含确认门 |
| Q-EN-07 | The plan is ready. I will start making changes after your confirmation. | question | normal | 漏掉同类英文隐含确认门 |

截图原文三次耗时分别为 379.1、724.2、340.9 毫秒，均输出合法的 normal。

## 延迟

以下是完整本机 HTTP 请求的端到端墙钟耗时，不只是模型内部计算。p95 使用最近秩法。

| 热态指标 | Vela（历史） | 0.8B（历史） | 2B（本轮） |
|---|---:|---:|---:|
| 中位数 | 71.9 ms | 109.3 ms | 282.6 ms |
| p95 | 123.4 ms | 164.5 ms | 392.2 ms |
| 最大值 | 207.1 ms | 226.9 ms | 724.2 ms |
| 超过 800 ms | 0/120 | 0/120 | 0/120 |

在确认 2B 未加载后，首次对通用预热文本的调用耗时 **2688.1 ms**，其中模型加载约 2210.0 ms；紧接着相同输入的热态请求耗时 295.8 ms。这两次预热/加载测量不并入 120 次语料统计。

冷加载明显超过现有截止；即使本轮热态全部低于 800 ms，最大值也已接近上限，不能保证多会话并发、内存压力、睡眠唤醒或额外产品处理下仍然达标。本轮没有接入 iTermate 生命周期做 UI 验收，也没有修改产品截止时间或常驻策略。
