# Qwen3.5-0.8B 与 Vela 回复状态分类比较

## 结论

本轮不建议用 Qwen3.5-0.8B 替换 Vela。在同一组固定助手回复、相同业务标签定义和本次运行配置下，Qwen 的误报明显更多，且没有解决截图里的误判。该结论只针对本次模型版本、后端、提示词与样本，不代表模型系列的总体能力，也没有比较 2B 或 4B。

## 安装与运行状态

- 机器：Apple M4，32 GiB 内存，macOS 26.5.1。
- 已通过 Homebrew 安装 Ollama 0.40.6，仅下载 `qwen3.5:0.8b`，模型文件共 1,244,131,636 字节，约 1.24 GB。
- 模型 digest：`d9c89605f39abfd9e8cb4fd3c099c203d7d17e82d7765b4266a0612402d88f1c`。
- 实际运行格式：safetensors、mxfp8、MLX 后端；服务报告参数量为 852.88M。模型加载后 `/api/ps` 报告 `size_vram` 为 1,328,982,336 字节；这不是整个 Ollama 进程的总内存峰值。
- Ollama 仅监听 `127.0.0.1:11434`，关闭云功能，未创建登录启动服务。正式分类设置 `think: false`、上下文 4096、temperature 0、seed 42、最大生成 32 token。
- 首次下载受到本机代理 Fake-IP 与 Ollama 地址检查冲突影响；使用现有显式本机代理后完成下载，未关闭地址安全保护。首次长下载在命令超时后从已下载片段续传成功。
- Homebrew 自动安装 Python 3.15、MLX、mlx-c，并升级 readline、sqlite 与 ca-certificates；默认 `python3` 等链接被 Homebrew 重链接，旧链接由 Homebrew 备份。这是安装的实际环境副作用，未宣称其他 Python 项目的兼容性已验证。
- 未改动 iTermate 产品源码、Pi 安装副本或当前模型配置，未重启 iTermate/Bridge。原有工作区已存在的其他改动没有被本任务处理。

## 评估方法

数据集为 [固定样本](../evidence/cases.json)，共 40 条完整助手回复：normal/question 各 20 条，每类中文、英文各 10 条。截图原文逐字核对来自原始 Pi 消息；其余 39 条为人工合成，包括完成报告、计算结果、自问自答、引用或代码里的问题、可选后续、自主进度、失败结束、确认、选择、授权和缺失信息请求。

标签定义是“最新助手回复是否请求或等待用户回答、选择、确认、授权或补充信息”，而不是语法上是否有问号。Vela 使用现有 `/v1/question` 产品接口；Qwen 使用相同业务说明和标签定义，以独立 system/user 消息调用 `/api/chat`。

兼容性预检只使用 `The work is complete.`，没有运行正式 40 条样本：

1. 当前 Ollama safetensors/MLX 后端对 `format` JSON Schema 返回 HTTP 501：`structured output is unavailable`，因此移除该参数。
2. 仅用自然语言要求 JSON 字段时，预检输出了错误的字段名。正式评估前在提示词末尾明确列出两个合法输出模板，标签定义未变。原预检脚本和结果均保留，没有把它们混入正式统计。
3. 此后冻结最终提示词、脚本和原始样本，正式比较中不再修改；严格校验 JSON 与标签，无效输出计作错误，没有宽松猜测或重试。两种后端的推理与输出适配不同，因此比较的是两个可运行配置，而不是受控到仅有参数量不同的实验。

每条回复、每个模型调用三次：每轮固定种子洗牌，交替两个模型先后，串行请求，共 240 次正式调用。三轮重复用于观察稳定性和延迟，**不是 120 个独立样本**。所有调用均成功并通过最终输出校验；没有因失败而删除样本。

样本 SHA-256：`ab4894e91d34e887c0ca8a05d9ea53bddb41831f2d71c40694b76c63505fdb91`。

## 分类结果

| 指标 | Vela 0.3B | Qwen3.5-0.8B |
|---|---:|---:|
| 正式调用数 | 120 | 120 |
| 正确分类 | 99/120（82.5%） | 68/120（56.7%） |
| 各轮正确样本数 | 33、33、33 / 40 | 22、23、23 / 40 |
| 普通回复被误报为等待 | 18/60（30.0%） | 52/60（86.7%） |
| 等待请求被漏报为普通回复 | 3/60（5.0%） | 0/60（0%） |
| 协议、HTTP 或输出格式错误 | 0 | 0 |
| 截图原文 | 三次均误报 question | 三次均误报 question |

分语言的重复调用正确数：Vela 中文 48/60、英文 51/60；Qwen 中文 32/60、英文 36/60。Qwen 在本配置下过度倾向 question；漏报为零并不抵消普通完成回复的大量误报。

Vela 的七条固定错例为 `N-EN-02`、`N-EN-04`、`N-EN-05`、`N-ZH-01`、`N-ZH-03`、`N-ZH-05`、`Q-ZH-07`。Qwen 至少一轮出错的案例共 18 条，详见原始结果的 `metrics.qwen.wrong_case_ids`；不是把“至少一轮出错”换算成单轮准确率。

## 延迟

以下为完整 HTTP 请求端到端墙钟耗时，包含输入处理和输出生成，不只是模型内部计算。p95 使用最近秩法。

| 热态指标 | Vela | Qwen3.5-0.8B |
|---|---:|---:|
| 中位数 | 71.9 ms | 109.3 ms |
| p95 | 123.4 ms | 164.5 ms |
| 最大值 | 207.1 ms | 226.9 ms |
| 超过现有 800 ms 截止 | 0/120 | 0/120 |

另行卸载 Qwen 模型后，首次重新加载并分类耗时 **1015.2 ms**，其中模型报告加载耗时约 839.6 ms，超过现有 800 ms 截止；紧接着相同输入热态耗时约 105.2 ms。该单次冷加载测量未并入热态数据集统计。Vela 没有卸载或重启，因此没有可直接比较的 Vela 冷启动数据。

800 ms 判断通过完整请求的实测耗时模拟，未在 800 ms 时提前取消请求；也没有将 Ollama 接入现有 iTermate 生命周期做端到端 UI 验收。

## 局限与下一步

- 只有一条真实故障回复，其他样本是合成数据，样本量小、标签由任务定义人工给定，且类别人为平衡。这里的正确率不是生产准确率或统计显著性结论。
- Qwen 使用一个英文零样本提示词，未做业务微调或多提示词对照。更简短中文提示词、不同输出协议、量化或后端可能产生不同结果，需要独立留出集验证，不能用同一测试集反复调优后宣称能力提升。
- 串行热态测量不代表多会话并发、睡眠唤醒、内存压力或冷启动体验。temperature 0 仍出现少量轮间差异；本次没有定位到数值精度或缓存等具体机制，不能据此声称原因已确定。
- 本轮保持 Vela 不变；如继续比较，优先评估 2B/4B 与独立留出集，而不是只靠提高置信度阈值解决本次高置信度误报。
- 未运行项目单元测试或测试套件；运行的是本任务明确授权的本地模型实测、Python 语法检查、数据一致性和统计复核。
