# Pi 会话摘要、归档与恢复

## 实时状态与只读恢复

Pi 集成仅在 iTerm2 的交互 TUI 中运行，并按明确的终端 Session ID 关联面板。`agent_start` 表示运行；最终使用 `agent_settled`，避免把重试、自动续跑或压缩之前的 `agent_end` 当作整个任务完成。`agent_settled.aborted` 表示中止，显示 `interrupted`，不会生成成功完成证据；明确 error 的结束保留失败结果。

正常 settled 后，问题判定在后台执行，hook 只等待有界状态上报，不等待模型完成；新一轮、分支切换、Session 切换或退出会取消旧请求。库存查询、模型生成和最后一次库存核验共用十秒总预算。输入为最后一条完整助手可见回复，不再按 3000 字符跳过；系统提示词与全文的 UTF-8 字节数加 1024 余量必须不超过 16384，作为模型上下文的保守上限。超限不截断后猜测，而是返回未知。

状态保留三种判定结果：确认需要用户回应为 `awaitingInput`；确认无需回应且没有未决工作时才是 `finished`；分类进行中、超时、不可用或无效结果为 unknown，不生成成功完成证据。明确的 confirm/select/input/editor 提示仍优先显示等待；custom UI 不默认视为提问。主 Agent 或可确认的子代理还在运行时继续显示 running，不能仅因主 Agent 已 settled 就宣布所有工作完成。

子代理通过进程内 Fleet v1 `status` 快照确认；已知零、已知存在活动和未知分别处理。`subagent:child-status` 的 started/stopping/stopped 只是即时刷新提示，不能代替快照；另有约两秒的轮询兜底。旧的零在子代理启动时失效，过期或失败的观察不能推出“没有子代理”。推送和私有 `status` 查询共用状态派生；查询验证 token、实例和原生 Session 身份，不调用模型、不归档、不推进 Pi。App 每两秒补查缺失状态，最多四个在途请求，每次三秒截止，并在响应后复核身份与连接代际。

正常／失败完成提供稳定的 `completionId`、Unix 秒 `completedAt` 和 `exitStatus`；最近最多 64 条 `recentCompletions` 随后续 running、idle 或 unknown 状态保留，`latestCompletion` 继续提供单条兼容字段；每个快照复制事件列表，下一轮不会改写已排队的快照。通知与成功计数按完成身份去重，能处理两次采样之间的多轮结束，无需刚好采到相邻的 running 和 finished 快照；中止、待回复和未知不新增成功记录。首次观察到的历史完成只建立基线，不补发通知；旧集成和普通 Shell 仍有状态转换兜底。这是当前 Pi 集成运行期的有界记录，Session 启动／重载清空；断开期间若超过 64 次完成而旧事件已被挤出，仍无法补齐全部次数，不是持久化任务日志。

运行／等待仍靠有限租约维持，状态 report 另有三秒总截止；断开后的迟到消息由来源身份、单调序列及代际检查拒绝。更新源码不会替换当前安装态集成，需要运行新版 App，并通过 Agents 安装更新后在 Pi 中 `/reload`。

## 实时任务标题

安装新版 Pi 集成并执行 `/reload` 后，交互式 Pi 会在启动、重载或切换分支后的安全空闲时，根据已有对话补生成简短中文任务标题；没有对话时不调用模型。每轮成功回复结束后也会在后台使用Local LLM设置中选择的本机Qwen3.5 2B或4B更新标题，不再使用当前Pi模型。面板的实时 Session 行优先显示这个标题，悬停文字可查看原始终端标题；仅通过明确的 iTerm2 Session ID 匹配，不按目录、名称或其他终端的 TTY 猜测。

输入只取当前分支最近四条用户消息和四条助手可见文本，每条最多保留开头与末尾各约1000字符，不发送隐藏思考、图片、系统指令或原始工具输出。标题调用无工具、不写入对话，不使用云端或旧Decision API；每次推理读取App保存的同一模型选择，分类与标题保持一致，所选模型不可用或请求中选择改变时不回退其他模型。每次推理后请求十分钟本地热驻留。标题提示词建议最多十六个元素，汉字逐字计数、连续英文技术词或缩写整体计一元素，并要求不含标点、空白和数字；十六元素、标点和数字要求仍是提示词指导。发布前另有短单行校验：结果必须非空、不含任何换行、最多 80 个 Unicode 标量；首轮不合格或达到 token 上限时，根据原对话和草稿调用同一本地模型再摘要一次；截断草稿不直接发布，第二轮须正常结束且通过相同校验，否则失败并保留旧标题，不机械清洗或截断。两轮绑定同一模型配置和库存 digest，共用六十秒总截止；通信大小、响应有效性、取消及会话身份保护仍保留。模型不能保证语义准确，也不能保证自动去除用户消息中的所有敏感内容。

生成期间或生成失败时保留上一条标题；没有可用摘要、集成未更新或活跃身份失效时，回退原始终端标题。新一轮工作会取消上一轮尚未完成的请求；切换 Session、分支、重载或退出会清除旧摘要和待执行请求，迟到结果不能覆盖新会话标题。摘要仅在当前 Pi 运行期间缓存。启动补生成与回复结束后的生成先等待约1.5秒，忙碌、有待处理消息或交互提示时继续等待空闲，不阻塞对话。状态查询仍不调用模型。已有标题由活跃 Pi 的发现元数据恢复，不因 App 重开而清空。Settings → **AI** → **Automatically Fill Missing Titles** 是共享的持久化开关，默认开启；关闭时，启动补生成和 App 发现补全均不为缺失标题调用模型，手动刷新和已有标题随成功回复更新的行为不变。

自动生成失败时，Pi 会显示不包含对话或供应商原始错误的提示，区分本地模型超时、调用失败和无效标题；单次本地 HTTP 请求十秒截止，标题生成总截止六十秒。对同一段连续未变化的对话最多自动尝试两次，第一次失败后至少等待10秒且会话空闲再重试；成功后相同内容不重复生成。达到上限后停止自动重试，可使用右键 **Refresh Session Title** 主动重试。启动、重载和分支切换会重置运行期缓存及重试预算，因此也可能再次调用本地模型。摘要发布后面板通常在下一次两秒发现轮询中更新，不改变 Agent 工作状态或完成计数。

新版 App 发现支持 `ensureTitle` 的空闲 Pi 实例缺少标题时，会通过认证端点请求补全；最多同时两个请求，同一实例与原生 Session 最多请求两次，至少间隔十秒，停止 App 时取消。端点重新检查开关、空闲、会话与分支身份，并复用集成已有的成功去重与两次生成预算；若标题已出现则直接返回，不覆盖它。没有对话时不调用模型。旧集成不支持该能力，需要安装更新并 `/reload`。这是独立的缺失标题补全动作，不把只读状态查询改为模型调用。

右键点击实时 Session 行，选择 **Refresh Session Title**，即可根据当前分支对话重新生成标题，无需发送新消息或等待下一轮回复。该操作仅调用本地小模型，即使对话未变化也会重新生成；不要求选择当前 Pi 模型。会话须空闲并加载支持手动刷新的新版集成；普通 Shell、旧集成、身份不明确或忙碌时菜单置灰。刷新期间显示 **Refreshing Session Title…** 并禁止对同一会话重复点击；刷新不锁定 Pi 输入、不改变工作状态，也不归档或关闭终端。模型失败保留原标题并在面板显示错误，新一轮或导航使请求过期时可在空闲后重试。

实时标题与归档摘要独立：前者用于识别当前工作，后者在用户选择归档时生成较完整的会话总结。

## 标题生成对比测试

`integrations/pi/session-title-model-comparison.test.ts` 调用生产的 `taskSummaryExcerpt` 和 `summarizeTask`，但显式注入诊断适配器用于比较，不改变应用固定使用本地小模型的默认路径。`task-summary.test.ts` 覆盖短单行校验、有效结果原样保留、无效草稿再摘要、第二轮仍无效时失败、取消及本地二分类标签。默认单元测试使用模拟网络，不调用真实模型；真实模型比较是单独的显式启用测试。

仅运行该测试文件：

```sh
tsx --test integrations/pi/session-title-model-comparison.test.ts
```

默认离线检查使用模拟适配器；生产标题函数要求非空、无换行且最多 80 个 Unicode 标量，不按十六元素、标点或数字做额外过滤，也不要求双方标题逐字相同。24 字等额外偏好仅用于比较质量，模型语义质量仍需人工核对。

真实比较只发送文件内固定的三个合成会话，不读取当前 Pi 会话、历史文件或 Pi 认证配置。远程侧需显式指定一个支持 Bearer 认证、`messages`、`max_tokens` 和字符串 `message.content` 的 HTTPS OpenAI 兼容 Chat Completions 接口；这不会自动选用当前 Pi 模型或其 OAuth 凭据。

```sh
export ITERMATE_TITLE_REMOTE_URL='https://your-provider.example/v1/chat/completions'
export ITERMATE_TITLE_REMOTE_MODEL='your-remote-model'
# 通过环境变量安全提供 ITERMATE_TITLE_REMOTE_API_KEY；不要写入仓库或测试输出。
ITERMATE_TITLE_COMPARE_LIVE=1 tsx --test integrations/pi/session-title-model-comparison.test.ts
```

启用后每个场景每侧最多调用两次（首轮及必要时的一次再摘要），三个场景每侧最多六次，可能消耗远程额度。配置缺失会明确失败，不静默跳过或更换模型。远程地址禁止内嵌凭据、查询参数和重定向；本地固定调用 `127.0.0.1:11434` 的 `qwen3.5:2b`，需事先安装并启动 Ollama，测试本身不会启动服务。诊断适配器使用标题函数的60秒总截止和64输出token；本地诊断关闭思考、使用32768上下文。生产直接本地调用使用16384上下文、64输出token和十分钟keep_alive。

每个场景的诊断输出保留双方生成标题、端到端耗时、24 字偏好与结构约束结果，任一侧失败仍保留另一侧结果。标题无需逐字一致；满足中文/格式等结构约束不等于任务识别准确，需要人工比较语义。测试不修改生产模型、会话标题、模型配置或用户集成安装副本。

## 使用入口

1. 在 **Settings → Agents** 安装或更新 Pi 集成，并在对应 Pi 中执行 `/reload`。
2. 等待主 Agent 和子代理结束，关闭未完成的 Pi 输入／选择弹窗。
3. 右键点击 Session 行，选择 **Archive Pi Session**，直接执行归档，不再显示确认弹窗。Pi 会先使用该会话当前配置的模型生成摘要（会消耗模型额度），再保存归档、退出并关闭对应分屏。
4. 展开主面板底部的 **Archive** 分区，点击归档行的 **Resume** 恢复；也可以在 **Settings → Archives** 点击 **Resume in iTerm2**。

面板 Archive 默认折叠，只显示标题；展开后显示归档名称、原工作目录及恢复入口。只有明确点击 **Resume** 按钮才恢复，点击行内名称、目录或空白区域不会恢复。悬停可查看生成的会话摘要、完整 Session ID、终端类型和归档时间；Settings 的归档条目也支持摘要悬停。旧归档没有摘要时显示缺省提示，仍可恢复，不自动调用模型补写。该分区与当前 Session 共用滚动区域，参与顶部菜单的 Expand All / Collapse All；折叠状态只保留在当前面板生命周期中。连接尚未就绪或没有当前 Session 时，Archive 仍可显示。展开只刷新列表，不会自动恢复或删除归档。

归档菜单仅在能明确匹配到一个活跃 Pi 会话、Pi 已空闲、没有排队输入或未发送的编辑器草稿，且没有活跃子代理时可用。运行中、身份不明确、集成未加载、临时 `--no-session` 会话等情况不会关闭终端。不是通过 Session 标题、项目路径或最近修改的文件猜测会话身份。

## 保存内容与隐私

Pi 集成通过 SDK 的 SessionManager 读取当前会话 ID、工作目录、原始文件位置、完整原生条目和当前分支位置，保存：

- 原生 JSONL 会话记录，包含历史分支。
- 一个不进入模型上下文的 `itermate.archive` 自定义锚点，使恢复定位到归档时选中的分支。
- 会话 ID、名称、工作目录、归档时间、原始文件位置、终端类型与 SHA256 清单。
- 当前 Pi 模型生成的中文简短摘要：会话目标、已做工作、结果或未完成事项。

摘要通过当前 Pi 进程的模型接口生成，不启动另一条 Pi CLI、不执行工具、不向原会话追加摘要提示词。输入使用当前分支经压缩与上下文编辑后的可见用户／助手文本及已有分支摘要，不传系统指令、隐藏思考、图片或原始工具输出；长内容保留开头与末尾摘录，因此摘要不是完整历史的替代品。调用使用当前模型及其配置的服务提供方，不能保证模型自动消除所有敏感信息。生成失败、取消、60秒超时、空结果或超长结果时不发布新归档、不退出 Pi，显示错误后可以重试。

原始 Pi 记录不删除。归档是点击时的会话快照，不是整个项目、外部文件、扩展内存状态或子代理工作区的备份；Pi 正常退出的清理钩子仍会执行。

归档位于当前用户 Application Support 的 `iTermate/ArchivedPiSessions` 下，每次独立目录。目录权限 0700、文件权限 0600。会话可能包含提示词、文件内容、工具输出或用户曾输入的凭据；归档不加密，不应上传、提交到 Git 或公开分享。

活跃 Pi 的发现信息位于用户配置目录 `.iTermate/pi-live`，通过私有 Unix socket 与随机凭据联系准确的进程。该目录和 socket 不对其他用户开放；同一用户权限下的恶意程序不在此隔离边界内。应用不会把连接凭据写入归档。

## 安全关闭

归档由目标 Pi 自己生成；摘要生成后重新检查会话身份、当前分支及空闲条件，再写临时目录、校验、持久化并原子发布。只有成功后才请求 Pi 正常退出；应用还会复核归档的 SHA256 和原生会话身份，并要求新归档包含摘要。新操作要求 Pi 已加载支持摘要的新版集成，旧集成需 `/reload` 后才能归档。

随后等待目标 Pi 进程退出，再检查终端是否仍由原父 Shell 占用。iTerm2 使用原生进程信息及可用的 Shell Integration 状态。身份变化、有新任务占用、Pi 未退出或无法确认安全时，**保留终端**并显示错误；已经保存的归档仍在列表中。

关闭仅针对归档会话对应的分屏，不关闭同一标签页的其他分屏；它是该标签页最后一个分屏时，由终端自然移除空标签页。终端已随 Pi 退出而关闭时，关闭操作视为已经完成。iTerm2 会短暂等待退出后前台进程及提示符刷新，发现另一存活进程则保留分屏；显式关闭不使用 force。若终端由自定义命令、包装器或特殊进程结构启动，可能无法确认原 Shell，此时请检查归档后自行关闭终端。

归档操作限制为 64 MiB 原生 JSONL；超限时不退出 Pi，应使用 Pi 自身的导出功能处理更大的会话。

## 恢复方式

恢复前检查归档文件摘要、Session ID 和工作目录。原工作目录不存在或记录损坏时拒绝恢复，不自动改用其他目录。

应用会在 `iTermate/ResumedPiSessions` 下生成可写副本，在原工作目录的新终端执行以下形式的命令：

```sh
pi --session '<归档中的-session-id>' --session-dir '<本次恢复副本目录>'
```

因此保留用户熟悉的 `pi --session <id>` 方式，同时通过明确的 `--session-dir` 避免命中原始文件或同 ID 的其他副本。ID 不硬编码。若自定义 ID 以 `.jsonl` 结尾（Pi 会将这种参数当成文件路径），改用恢复副本的明确文件路径。路径和参数使用 shell 引号，不向已有会话粘贴命令。

恢复使用 `/bin/zsh -lic` 加载用户的登录交互环境；该环境必须能找到 `pi`。只有新 Pi 集成报告已打开目标副本时才确认恢复。命令缺失、权限不足或集成没有加载时，终端可能已打开，但应用会提示恢复未确认；归档不受影响。检查终端提示后再重试，避免重复打开。

归档快照始终保留，恢复后的新消息写入副本；列表不会自动删除归档。已发现相同 Session ID 的活跃 Pi 时，拒绝重复恢复。

## 验证边界

代码构建、AppleScript 编译和原生 SessionManager 格式兼容检查，不等同于真实用户终端的归档／关闭／恢复验收。更新源码后应由用户自行重新构建运行 App，再重载 Pi 集成。开发期间不应为了验证擅自归档或关闭真实会话。
