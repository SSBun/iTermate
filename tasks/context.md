# 工作区上下文

## 工程与组件

- 菜单栏入口使用 `iTermate/Assets.xcassets/StatusIcon.imageset/status-icon.png` 中用户指定的 `terminal-icon.png` 高分辨率转换资源；源图保留 554×549px、可见边界约 475×412px，`MenuBarExtra` 通过预设 `NSImage.size` 为 18pt 高的 `Image(nsImage:)` 控制运行时大小，再使用 template rendering 适配浅色/深色菜单栏；资源说明记录在 [`THIRD-PARTY-NOTICES.md`](../THIRD-PARTY-NOTICES.md)。——权威来源：[`iTermateApp.swift`](../iTermate/iTermateApp.swift)、[`StatusIcon.imageset`](../iTermate/Assets.xcassets/StatusIcon.imageset) 与 [`project.yml`](../project.yml)
- XcodeGen 的 [`project.yml`](../project.yml) 是 Xcode 工程配置的规范来源，生成的 [`iTermate.xcodeproj`](../iTermate.xcodeproj) 可直接构建；修改 target 或构建设置时应更新 YAML 后重新生成工程。——权威来源：[`project.yml`](../project.yml)
- 应用 shell 使用 SwiftUI `App`，由 `MenuBarExtra(.window)` 提供 Bridge 摘要与 Settings/Quit，由浮动面板左下角的齿轮入口和 `Settings` scene 提供 Basic、Agents、About 标签；`AppDelegate` 启动共享 Store、浮动面板与完成通知控制器。macOS 14+ 用 `SettingsLink`，macOS 13 用 `showSettingsWindow:` fallback。——权威来源：[`iTermateApp.swift`](../iTermate/iTermateApp.swift)、[`SettingsViews.swift`](../iTermate/SettingsViews.swift) 与 [`SessionNotifications.swift`](../iTermate/SessionNotifications.swift)
- 窗口几何与 iTerm 语义分层：`PanelFollower` 在 Swift 侧通过 Core Graphics 以 30Hz 跟随 active iTerm 的可见窗口；`ItermWindow.frontmost()` 要求 iTerm 为系统前台应用，并从可见 layer-0 候选中选择最大窗口，以排除 Close Tab 等模态提示框。iTerm 失去焦点或没有可见窗口时面板隐藏。Window/Tab/Session 层级及操作由 Python Bridge 提供，因此当前无需 Accessibility 权限；若需要多个主 iTerm 窗口的精确前台识别，应改用窗口 ID/Accessibility 并复查。——权威来源：[`iTermateApp.swift`](../iTermate/iTermateApp.swift)、[`PanelLayoutTests.swift`](../iTermateTests/PanelLayoutTests.swift) 与 [`ItermBridge.swift`](../iTermate/ItermBridge.swift)
- Bridge 作为 App resource 安装到 iTerm2 AutoLaunch，使用文件锁保证单实例，并通过用户私有目录中的 Unix Socket 与 App 交换 versioned JSON Lines；当前协议与 Bridge 版本均为 5，修改协议时必须同步递增/校验 Swift、Python 与随 App 分发的 integration。由于 App 更新不会自动重装已启用的 integration，Bridge v5 仍仅对 `setSessionStatus` 接受 v4 请求。——权威来源：[`iTermateBridge.py`](../iTermateBridge/iTermateBridge.py)、[`ItermBridge.swift`](../iTermate/ItermBridge.swift)、[`integrations`](../integrations) 与 [`project.yml`](../project.yml)
- Bridge v5 同步全量 Window/Tab/Session 快照及命令状态；Session 标题和路径每 2 秒从 iTerm 动态变量读取，对象属性仅作回退，因此标题变化无需 Layout 事件或重启。普通 shell 命令由 Shell Integration PromptMonitor 观察；Pi/Codex 长驻 CLI 改由原生 agent lifecycle integration 报告 working/finished/idle，并优先于 PromptMonitor，退出后再释放给 shell fallback；Pi lifecycle handler 会等待匹配 request ID 的 Bridge `actionResult`，避免 fire-and-forget 丢失 settled 状态。完成状态不会按时间消失，只在完成后再次激活该 Session 时清除。——权威来源：[`iTermateBridge.py`](../iTermateBridge/iTermateBridge.py)、[`Pi integration`](../integrations/pi/iTermate-integration.ts)、[`Codex hook`](../integrations/codex/iTermate-hook.py) 与 [`ItermBridge.swift`](../iTermate/ItermBridge.swift)
- `SessionNotificationController` 观察所有 Session 的 `running → finished` 快照转换；全局开关默认关闭，开启时请求 macOS 通知权限，后续启动也会重新确认当前 App bundle 的授权，并对普通 shell 与 agent 完成都发送带 Session 名称和结果的原生通知。初始 finished 快照与重复 finished 快照不会通知；通知携带 Session ID，用户点击后复用 Bridge 激活请求选择对应 Session 并将 iTerm 置前；系统拒绝授权时关闭开关，发送错误写入日志。——权威来源：[`SessionNotifications.swift`](../iTermate/SessionNotifications.swift)、[`SettingsViews.swift`](../iTermate/SettingsViews.swift)、[`iTermateApp.swift`](../iTermate/iTermateApp.swift) 与 [`iTermateBridge.py`](../iTermateBridge/iTermateBridge.py)
- Agents Settings 列出 Claude Code、Codex、OpenCode、Cursor CLI、Kimi Code、Pi 与 omp；当前仅 Pi/Codex 可管理。两套 integration 资源随 App bundle 分发；Pi 开关管理 `~/.pi/agent/extensions/iTermate-integration.ts`，Codex 开关只合并/移除 `~/.codex/hooks.json` 中带 `_iTermate` 的 entries 并管理 helper，不改其他 hooks。已有 Pi Session 需 `/reload`，Codex 新 hooks 需在 `/hooks` 中信任。——权威来源：[`AgentIntegrations.swift`](../iTermate/AgentIntegrations.swift)、[`Pi integration`](../integrations/pi/iTermate-integration.ts)、[`Codex hook`](../integrations/codex/iTermate-hook.py) 与 [`project.yml`](../project.yml)
- 面板可按 Window 平铺其所有 Session，或按 Session 的精确当前目录跨 Window/Tab 分组；Window 或文件夹路径只显示在 section header，Session 行只显示标题与状态图标。Window 样式默认为每个 Tab 显示弱化小节标题并缩进其 Session，可在 Basic Settings 中关闭；Project Path 样式不显示 Tab 标题；同组 Session 行使用紧凑间距，Window/Tab/Project Path 标题前保留更大垂直留白。标题栏配置菜单按 Group By、Display、Sections 分区，各操作项使用语义图标且分组项保留原生选中标记；Window、Tab 和 Project Path 标题均可临时折叠，并支持全部展开/折叠。样式与 Tab 标题开关持久化，折叠状态仅保存在当前运行时；点击 Session 会选择父 Tab、聚焦 pane 并将 Window 置前，当前聚焦标记由 Bridge 的全局当前 Session ID 生成，保证每份快照最多一个聚焦 Session；每行的独立关闭按钮通过 Bridge 请求 iTerm 原生非强制关闭。——权威来源：[`ItermBridge.swift`](../iTermate/ItermBridge.swift)、[`SettingsViews.swift`](../iTermate/SettingsViews.swift) 与 [`iTermateApp.swift`](../iTermate/iTermateApp.swift)
- `AppSettings` 是面板宽度、Session 列表样式、Tab 标题和完成通知开关的共享权威状态：全部配置从用户 `~/.iTermate/config.toml` 读取并写回，不使用 `UserDefaults` 或旧配置迁移；面板仍可通过原生边缘拖拽在 180–600pt 之间调整，左右边缘通过带 `.activeAlways` 的 `NSTrackingArea` 显示水平调整光标；默认宽度为 260pt。面板高度始终匹配 iTerm，与 iTerm 间隔 8pt，优先放右侧，空间不足放左侧，再不足则覆盖在可见屏幕内。——权威来源：[`SettingsViews.swift`](../iTermate/SettingsViews.swift)、[`iTermateApp.swift`](../iTermate/iTermateApp.swift)、[`PanelLayout.swift`](../iTermate/PanelLayout.swift) 与 [`PanelLayoutTests.swift`](../iTermateTests/PanelLayoutTests.swift)
